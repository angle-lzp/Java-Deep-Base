## VLLM 指令

以下命令使用 Bash/Linux shell 语法，多行命令使用 `\` 续行；`jq` 用于筛选和格式化 JSON，需要提前安装。不使用 `jq` 时，可直接执行管道前的 `curl` 请求查看原始响应。

默认服务地址为 `http://localhost:8000`。请求中的模型名称应替换为 `/v1/models` 返回的实际 `id`；如果服务配置了 API Key，请在受保护的请求中添加 `-H "Authorization: Bearer $VLLM_API_KEY"`，并提前设置该环境变量。

### 0.Gemma模型设置动态视觉配置 max_soft_tokens
* 当前 vLLM 主分支的 Gemma 4 代码也只将这五个值识别为有效选项；对于其他值，token 预算计算不会将其作为有效覆盖值处理
```shell
# max_soft_tokens 的默认值是280，可选值为：70、140、280、560、1120

# docker-compose.yml中的配置
  # 单次调度允许处理的最大 Token 总数
  - --max-num-batched-tokens
  - "4096"

  # 之前 0.95 因空闲内存不足启动失败
  # 这里先使用相对保守的 0.70
  - --gpu-memory-utilization
  - "0.70"

  - --mm-processor-kwargs
  - '{"max_soft_tokens":1120}'
```

### 5.查看模型详情和服务上下文上限

```shell
# 查看完整模型信息
curl -sS http://localhost:8000/v1/models | jq .

# 只查看常用字段
curl -sS http://localhost:8000/v1/models \
  | jq '.data[] | {id, root, parent, max_model_len, permission}'
```

| 字段 | 说明 |
| --- | --- |
| `id` | API 请求使用的模型名，可能是部署时配置的别名 |
| `root` | 基础模型标识或部署路径，具体取决于版本和部署配置 |
| `parent` | 父模型信息，例如部分 LoRA 模型 |
| `max_model_len` | 当前服务配置的最大上下文长度 |
| `permission` | OpenAI 兼容协议中的权限信息，不等同于模型能力清单 |

`max_model_len` 是服务运行时限制，不一定等于模型原生支持的上下文上限。`created` 也不能当作模型训练或发布时间。

### 6.查询 vLLM 版本

```shell
curl -sS http://localhost:8000/version | jq .
```

返回的 `version` 可用于判断当前部署支持哪些接口和启动参数。

### 7.查询当前服务支持的接口

```shell
# 列出 OpenAPI 中的接口路径
curl -sS http://localhost:8000/openapi.json | jq -r '.paths | keys[]'

# 筛选模型、分词和运行状态相关接口
curl -sS http://localhost:8000/openapi.json \
  | jq -r '.paths | keys[]' \
  | grep -Ei 'model|token|version|health|load|metric|info'

# 查看分词接口的请求定义
curl -sS http://localhost:8000/openapi.json | jq '.paths["/tokenize"]'
```

也可通过浏览器访问 `http://localhost:8000/docs` 查看交互式接口文档。

接口取决于 vLLM 版本、启动参数和代理配置，应以当前服务的 OpenAPI 为准；关闭 FastAPI 文档后，`/docs` 和 `/openapi.json` 可能不可用。不要默认存在 `/model_info`、`/get_model_config` 或 `/v1/models/{id}` 等接口。

### 8.查询文本 Token 数量和上下文上限

```shell
curl -sS -X POST http://localhost:8000/tokenize \
  -H "Content-Type: application/json" \
  --data '{
    "model": "Qwen/Qwen3.5-9B",
    "prompt": "你好，请介绍一下你自己。"
  }' | jq .
```

主要返回字段：

| 字段 | 说明 |
| --- | --- |
| `count` | 输入文本分词后的 Token 数量 |
| `tokens` | Token ID 列表 |
| `max_model_len` | 服务实际配置的上下文长度上限 |

聊天请求可以使用 `messages`，统计包含聊天模板的输入长度：

```shell
curl -sS -X POST http://localhost:8000/tokenize \
  -H "Content-Type: application/json" \
  --data '{
    "model": "Qwen/Qwen3.5-9B",
    "messages": [
      {"role": "system", "content": "你是一个有帮助的助手。"},
      {"role": "user", "content": "请介绍一下你自己。"}
    ],
    "add_generation_prompt": true
  }' | jq .
```

聊天模板也会占用 Token，因此结果通常比只统计用户文本更接近实际聊天请求。输入和生成内容需共同满足服务的上下文预算。

### 9.查询 Tokenizer 详情（需要版本支持并显式启用）

支持此功能的版本，需要在原有服务启动配置中添加：

```text
--enable-tokenizer-info-endpoint
```

启用后查询：

```shell
curl -sS http://localhost:8000/tokenizer_info | jq .
```

可用于查看服务返回的 Tokenizer 配置，例如聊天模板、特殊 Token 等；实际字段以部署版本为准。

该参数属于启动配置，不是查询命令。已有服务不要重复启动，应先确认版本支持，再按部署流程调整配置。接口可能暴露模板和配置细节，不建议无保护地对公网开放。

### 10.查询当前服务负载

需要在原有服务启动配置中启用：

```text
--enable-server-load-tracking
```

查询：

```shell
curl -sS http://localhost:8000/load | jq .
```

典型响应：

```json
{
  "server_load": 0
}
```

`server_load` 反映被跟踪的在途请求负载，不是 GPU 利用率；`/load` 也不是加载模型的接口。未启用跟踪时，不要据此判断服务是否空闲。

### 11.筛选请求队列、KV Cache 和 Token 指标

```shell
curl -sS http://localhost:8000/metrics \
  | grep -E '^vllm:.*(num_requests|cache_usage|prompt_tokens|generation_tokens|time_to_first_token|e2e_request_latency)'
```

重点观察：

- 正在运行和等待的请求数。
- KV Cache 使用情况。
- 输入、输出 Token 计数。
- 首 Token 延迟和请求端到端耗时。

不同版本的指标名称可能变化；筛选无结果时，先查看完整 `/metrics` 响应。Token 计数通常是累计值，吞吐率需要结合采样时间差或 Prometheus `rate()` 计算。

KV Cache 使用率不等于 GPU 总显存使用率。实际 GPU 利用率和显存需在部署服务器上查询：

```shell
nvidia-smi

# 每秒采样一次；按 Ctrl+C 停止
nvidia-smi \
  --query-gpu=index,name,memory.used,memory.total,utilization.gpu \
  --format=csv -l 1
```

### 12.查看模型结构、精度和量化配置（需要访问模型目录）

标准 `/v1/models` 不会完整返回模型层数、隐藏维度和量化配置。需要在部署服务器上读取实际模型目录中的配置文件：

```shell
# 替换为服务器上实际模型目录，不是 API 模型别名
MODEL_DIR="/path/to/model"

# 查看完整模型配置
jq . "$MODEL_DIR/config.json"

# 提取常用配置，多模态模型的文本参数可能位于 text_config 中
jq '{
  architectures,
  model_type,
  dtype,
  torch_dtype,
  quantization_config,
  text_config,
  vision_config
}' "$MODEL_DIR/config.json"

# 单独查看文本结构相关参数
jq '(.text_config // .) | {
  num_hidden_layers,
  hidden_size,
  num_attention_heads,
  num_key_value_heads,
  vocab_size,
  max_position_embeddings,
  rope_scaling
}' "$MODEL_DIR/config.json"
```

| 字段 | 说明 |
| --- | --- |
| `architectures`、`model_type` | 模型架构和类型 |
| `num_hidden_layers`、`hidden_size` | 层数和隐藏层维度 |
| `num_attention_heads`、`num_key_value_heads` | 注意力头和 KV 头数量 |
| `vocab_size` | 词表大小 |
| `max_position_embeddings`、`rope_scaling` | 上下文和位置编码相关配置 |
| `dtype` / `torch_dtype` | 模型配置声明的数据类型 |
| `quantization_config` | 量化配置，若存在 |
| `text_config`、`vision_config` | 部分多模态模型的文本、视觉配置 |

配置缺失时，对应筛选字段可能为 `null`。模型配置声明的精度和上下文不一定等于部署时的实际设置，应结合启动参数和日志确认。若模型目录在容器内，需要进入对应容器或读取实际挂载目录。
