## Teams Develop (ChatBot)
### 1.Teams开发ChatBot准备
* [Teams开发ChatBot](https://docs.microsoft.com/zh-cn/azure/bot-service/?view=azure-bot-service-4.0)

* Teams 云服务访问公司内部的ChatBot后端 - 需要提供一个Teams能访问的HTTPS Messaging Endpoint

```text
Teams
   ↓
你的 Chatbot 后端
   ↓
Azure OpenAI 只作决策
   ↓
你的 Chatbot 后端收到 tool_calls
   ↓
你的 Chatbot 后端访问 API / DB
   ↓
你的 Chatbot 后端把结果发给 Azure OpenAI
   ↓
Azure OpenAI 整理答案
   ↓
你的 Chatbot 后端
   ↓
Teams
```

**一.实现版本**
**方案一：直接使用 Azure OpenAI Tool Calling**
```text
Teams SDK
+ Azure OpenAI SDK
+ 自定义 Tool Registry

适合：
只有 3 到 10 个工具；
主要是内部 API 和 DB 查询；
调用流程比较固定；
希望减少框架依赖；
需要清楚控制每次函数调用。
```

**方案二：使用 LangChain Agent**
```text
Teams SDK
+ LangChain / LangGraph
+ Azure OpenAI
+ Tools

适合：
工具比较多；
有复杂的分支和多步骤工作流；
需要暂停、恢复和状态管理；
需要人工确认节点；
需要用 LangGraph 构建状态图。

识别用户请求
   ↓
检查权限
   ↓
查询 CMDB
   ↓
如果服务器异常，查询监控告警
   ↓
如果存在告警，查询关联工单
   ↓
生成诊断建议
```

**方案三：使用 LlamaIndex Agent**
```text
Teams SDK
+ LlamaIndex Agent
+ Azure OpenAI
+ Query Engine / Tools

适合：
除了 API 和 DB，还要搜索 Word、PDF、SharePoint 文档；
需要 RAG；
需要构建向量索引；
需要多个 Query Engine；
希望把 Query Engine 直接包装成 Agent Tool；
有结构化和非结构化数据混合查询。

LlamaIndex 支持将普通函数封装为 FunctionTool，也支持把已有的 Query Engine 包装为 QueryEngineTool，这使它比较适合同时连接实时 API、数据库和企业文档知识库。
```

**二.完整架构**
```text
┌─────────────────────────┐
│ Microsoft Teams 用户     │
└────────────┬────────────┘
             │ 发送消息
             ▼
┌─────────────────────────┐
│ Teams / Bot Channel      │
└────────────┬────────────┘
             │ HTTPS
             ▼
┌──────────────────────────────────────────┐
│ 你开发的 Chatbot 后端                     │
│                                          │
│  1. Teams 消息处理器                      │
│             ↓                            │
│  2. LangChain / LlamaIndex Agent         │
│             ↓                            │
│  3. Tool Registry                        │
│       ├── get_server_status              │
│       ├── get_incident                   │
│       └── search_employee_asset          │
│             ↓                            │
│  4. API Client / Database Client         │
│             ↓                            │
│  5. 权限、日志、审计、脱敏                │
└──────────┬─────────────────┬─────────────┘
           │                 │
           │ HTTPS           │ VPN/专线/内网
           ▼                 ▼
┌──────────────────┐  ┌───────────────────┐
│ Azure OpenAI     │  │ 公司内部 API / DB │
└──────────────────┘  └───────────────────┘

```

> 注：
**Teams是云服务所以ChatBot后端需要暴露一个URL给Teams用于接收用户发送的消息，所以最后还是需要本地的API需要暴露给公网（这是避免不了的）。**
**反向代理 → 外提供公共HTTPS地址 → 通过安全入口转发到内部服务器（ChatBot后端）**

**三.创建（申请）一个Bot**
```text
Entra App Registration
负责 Bot 应用身份

Azure Bot Resource
负责连接 Teams Channel 与 Messaging Endpoint

Teams App Manifest
告诉 Teams 应用名称、图标、Bot ID、支持范围

Chatbot 后端
真正接收消息、调用 Agent、访问 API/DB、回复消息
```

**四.最终详细架构**
```text
用户打开 Teams
    ↓
Apps → IT Assistant
    ↓
一对一聊天窗口
    ↓
Teams / Bot Channel
    ↓ HTTPS
Azure Bot Resource
    ↓ HTTPS POST
https://chatbot.company.com/api/messages
    ↓
企业 WAF / NGINX / F5
    ↓
公司内部 Chatbot Backend
    ├── Teams SDK Activity Handler
    ├── Agent Orchestrator
    ├── Azure OpenAI Tool Calling
    ├── Tool Registry
    ├── Internal API Client
    ├── Database Repository
    ├── Authorization
    └── Audit Logging
    ↓
通过当前消息上下文调用 send()
    ↓
Azure Bot / Teams Channel
    ↓
用户的 Teams 聊天窗口
```

### 2.技术选型建议

#### 方案 A：Teams SDK + Azure OpenAI

```text
这是我最推荐你的方案。

适用于：

机器人主要运行在 Teams。
需要自己写工具调用逻辑。
需要连接内部数据库、API。
需要精确控制身份、权限、日志。
公司允许使用 Azure OpenAI 或 Microsoft Foundry。

建议技术栈：

Plain Text
语言：TypeScript
运行时：Node.js 24+
Teams 接入：Teams SDK
开发工具：Microsoft 365 Agents Toolkit
模型：Azure OpenAI / Microsoft Foundry
部署：Azure App Service 或 Azure Container Apps
认证：Microsoft Entra ID + Teams SSO
机密管理：Azure Key Vault
监控：Application Insights

Teams SDK 当前支持 JavaScript 和 C# 正式版本，Python 仍处于预览状态。官方最新快速入门要求 Node.js 24 或更高版本，并推荐配合 Teams Developer CLI 和 Microsoft 365 Agents Playground。

```

#### 方案 B：Microsoft 365 Agents SDK

```text
适用于机器人将来需要同时运行在：

Teams
Microsoft 365 Copilot
Web
Outlook
其他消息平台

Microsoft 365 Agents SDK 更像一个跨渠道通信与状态管理框架，它不绑定具体大模型，可以配合 Azure OpenAI、Semantic Kernel、LangChain 或其他编排组件。
```

### 方案 C：Copilot Studio

```text
如果工具比较简单，例如：

查询 SharePoint。
查询 Dataverse。
调用 Power Automate。
查询固定企业知识库。
IT 部门希望低代码维护。

可以考虑 Copilot Studio。
```

```text
但如果你需要：

动态 SQL 查询。
复杂 API 编排。
严格的代码级权限控制。
自定义缓存和审计。
较复杂的多工具调用。

那么 Teams SDK 会更合适。
```
